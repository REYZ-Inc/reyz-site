# ADR-0014: 公開ページのCSS・JavaScriptを内容で版管理する

## 文脈

2026-11-16、PR #55の全関門とPages配備が成功した後、公開サイトに新しいHTMLと古いCSSが同時に読み込まれる状態を確認した。Homeのリンクに `hero-route` がある一方、読み込まれた `site.css` は560規則で同セレクタを含まず、疑似要素の矢印も存在しなかった。通常の再読み込み後も同じ状態だった。どのキャッシュ層に旧応答が残ったかは特定していない。

HTMLが固定名のCSS・JavaScriptを参照するため、内容の変更をURLから区別できなかった。配備の成功とローカルブラウザ検証だけでは、公開経路で版が揃うことを立証できない。

## 選択肢

1. 利用者へキャッシュの削除を依頼する。公開物の版管理の問題が残る。
2. 配備ごとにCDNのキャッシュを消す。別の権限と配備依存が増え、既に保存されたブラウザ側の応答は同じURLのままになる。
3. 内容のSHA-256からファイル名を生成し、HTMLがその版を参照する。

## 決定

3を採用する。対象は `site.css`、`site.js`、`field-renderer.js`、`experience.js`、`manual.css`、`manual.js` の6入口。`build/build.py` がcanonicalファイルの内容からSHA-256の先頭16桁を求め、同じ `assets/` 内に `site.<hash>.css` 等の内容が同一のファイルを出力する。各HTMLの参照を対応する版へ置き換える。

編集元の固定名ファイルは維持する。既に生成した版付きファイルも削除せず、古いHTMLからの参照を保つ。`SITE_OUT` はリポジトリのcanonical資産から版付き入口を生成する。時刻やコミット番号に依存させず、同一の内容から同一の公開物を再生成する。

## 帰結

- CSSの相対URLとmanualの相対module importは、同階層を維持するため変更しない。
- 今回不変のmanual子module、PDF原稿、フォント、固定ライブラリ、画像はこの6入口の版管理の対象に含めない。全依存グラフの更新を保証する設計ではない。今後これらを更新するときは、その取得URLと依存元を合わせて検証する。
- HTML自体のキャッシュ方針、DNS、CDN設定、秘密情報、セキュリティ設定は変更しない。新HTMLが読み込まれた後の入口資産の整合を対象とする。
- フォームの試験用設定差替えは固定名と版付き名の双方を対象にし、既存の送信先・Turnstile検証を維持する。
- 公開参照・内容hash・再現性・内容変更時のURL変更を回帰検査し、必須の全関門の後に公開画面で版を確認する。
