# ADR-0016: 全ページの表示と相談の継続を仕上げる

## 文脈

2026-11-19（JST）、CEOは既存サイト全体の洗練まで完了するよう指示した。ADR-0015による情報構造を公開した後の監査で、スクロール中のヘッダーの透け、用途に対して大きすぎる補助ページの冒頭、制作映像と説明の不一致、相談内容の引き継ぎ漏れ、古い非同期応答による上書き、結果不明時の重複送信リスクを確認した。

## 選択肢

1. 装飾と説明を増やし、操作の境界条件を現状のままにする。
2. 別サイトを作り、固定情報と公開経路を移し替える。
3. 既存の情報構造・制作元・公開経路に集約し、表示、説明、操作の不整合を修正する。

## 決定

3を採用する。実装は現在の生成元と正規のCSS・JavaScriptへ行い、生成HTMLと内容hash付き資産を再生成する。公開は従来どおりCEOによるPRマージで行う。

- 全ページ共通の固定ヘッダーとモバイルメニューを読みやすくし、Contact・Legal・404は目的の操作と本文へ早く届く構成にする。
- 制作の説明には、以前この作業で生成された撮影準備の映像から適切な区間を使い、AI生成のイメージ映像であると明示する。これはADR-0015のCreative実写素材選択だけを更新する。Creatorの出典表示とHomeの独自3D映像は保持する。
- 見本・料金試算・AIの説明を平易にし、固定の提供内容、料金、会社情報、実績に関する方針は変えない。
- 利用者の選択、未返信の発話、未送信の下書きを、本人が相談へ進む操作に応じて保持する。見本の受注・承認・公開・精算を実績として送らない。長文を黙って切り詰めない。
- 選び直し時には古い要求を中断し、選択世代でも応答を照合する。応答待ちに期限を設ける。
- 送信対象は確認済み内容へ固定し、同時に一つだけ処理する。通信断・サーバーエラー・応答期限は受付結果が不明な場合があるため、自動再送しない。処理前のTurnstile拒否への既存対応は保持する。

## 帰結

- 素材は新しいURLで追加し、既存URLを参照するキャッシュのため旧資産を保持する。
- 既存の受入検査を維持し、遅延応答・長文引き継ぎ・二重操作・結果不明をChromiumとWebKitで再現する回帰検査を追加する。追加検査はlocalhostの模擬受付だけを使い、外部のメール・モデル呼出しを行わない。
- 生成・構文検査、実ブラウザ検査、本番公開を別の状態として記録する。ローカル環境でブラウザが起動できない場合は、既存のGitHub CIで実行し、画面証跡を取得して判定する。
- 一般的な美的評価や世界順位を、測定済みの事実として記載しない。
