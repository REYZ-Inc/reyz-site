# ADR-0013: REYZ の体験を独自描画と実原稿で構成する

部分更新: Home冒頭の映像とCreativeの構図選択は、[ADR-0015](0015-customer-led-site-structure.md)により更新。残る粒子描画・経路選択・実原稿閲覧は維持する。

## 文脈

2026-11-16、CEOはコーポレートサイト全体の確認と、REYZの方向性にふさわしい独自の表現を指示した。既存ページの文言と章の位置には決定台帳による契約がある。汎用的なブロックの追加や架空の実績で見栄えを補わず、訪問者の選択と表示の関係を明確にする必要がある。

## 選択肢

1. 見出し・色・CSSのみ変更する。描画と操作の課題が残る。
2. サイトを別フレームワークへ全面移行する。今回の表現に不要な配信・更新経路の変更が増え、確定した本文や機能の回帰範囲が広がる。
3. 既存の公開経路と意味構造を保持し、目的に応じた描画基盤・CG素材・操作・実原稿の閲覧を独立した層として実装する。

## 決定

3を採用する。共通の形状計算からWebGL描画を分離し、利用不能・context loss時にはCanvas2Dへ切り替える。Creatorの経路選択とCreativeの構図は、有限時間・可視時だけのCanvas描画で応答する。Creativeの素材は独自のBlenderシーンから生成する。マニュアルの閲覧は元PDFの実ページを必要な時だけ読み込み、生成PDFと同じ名称・配色を反映する。

実装上の都合を来訪者向けの説明に加えない。全ページの見出しと本文はHTMLに保持し、WebGLやCanvasに本文を閉じ込めない。確認できる範囲をCIで検証してから通常のPR・Pages配備を通す。

## 帰結

- 新しい実行時ライブラリ、CDN、バックエンド、秘密情報を追加しない。
- 既存の章座標と本文表示の同期を保ち、QAは実際のGPU/2Dバッファの画素を測定する。
- 読み込み、GPU、動きを減らす設定、非表示、幅の異なる画面を個別に検証する。モックの合格を実GPU検証として扱わない。
- CGのWebPは1440×810、45,752 bytes。シーンコードと生成条件をリポジトリで管理する。素材が読めない場合も操作とCanvasの代替構図を維持する。
- 原稿から作る4サンプルは個別のbytesとSHA-256を持つ。重いPDFエンジンとは別に遅延取得する。
- マニュアル生成のADR-0012は維持する。フォーム送信、実モデルの呼出し、実績の主張を今回の装飾に混在させない。
