# ADR-0015: 顧客の判断順に構造を整理し、意味のある媒体へ集約する

## 文脈

2026-11-18、CEOはサイト全体の構造を再検証し、不要な説明や挿入をなくし、画像・アニメーション・実写を含む複数の制作手段で仕上げるよう指示した。従前のページには、困りごと・比較・約束の重複、実写の背景と端末枠での二重表示、企業向けの複数の独立した操作見本があった。

## 選択肢

1. 全節を維持して装飾を追加する。
2. 既存のサイトを別のフレームワークや公開サービスで作り直す。
3. 既存の公開経路と固定情報を保ち、顧客が判断する順に内容を整理して、各媒体の目的を一つに絞る。

## 決定

3を採用する。Creatorは収益の入口と条件、Creativeは提供範囲・案件の流れ・費用、AIは製品の役割と次の仕事に残る価値の順にする。企業の主要な操作見本は一案件のフルサイクルへ集約し、短い表現確認は補足として開く。

Homeの最初の粒子の∞を、既存の自社Blenderシーンからレンダリングした本物の動画へ置き換える。CreatorとCreativeは、利用条件を確認した実写をそれぞれ一面で見せる。旧Creativeの構図選択CGと重複した端末合成を撤去する。共有用画像は公開ブランド素材を参照して画像生成ツールで制作する。

これはADR-0013のうち、Creativeの構図選択とHome冒頭の描画方式を更新する。後続章の粒子描画、Creatorの経路選択、実原稿のマニュアル閲覧は維持する。

## 帰結

- 提供内容・固定コピー・会社情報・料金条件を、装飾の都合で改定しない。
- 各媒体はブランド、活動・制作のイメージ、操作結果の理解という役割を持つ。ストック映像を顧客実績として示さない。
- 仕事の再利用は、実行機能・完了確認・変更の影響範囲を顧客の言葉で説明する。顧客記録・秘密情報と共通機能を分け、他案件への再利用は許諾範囲に限る。
- 同じ映像の重ね置き、削除した構造専用の実装、重複した説明を残さない。
- 動画は読み込み、手動停止、画面外停止、再入場、動きを減らす設定、破損素材を実ブラウザで検査する。見本内の公開・承認・精算と商用サービスの実動作は区別する。
- 既存のGitHub PR・CEOマージ・Pages自動配備を維持し、別の本番サイトを作らない。
