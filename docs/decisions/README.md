## 規則（DEC-20261027-09）
- サイトの決定は台帳に 1 行ずつ追記する。文言はロウ（CEO）の言葉のまま、日時つき。覆すときは行を書き換えず、新しい行で「DEC-xxx を改訂」と書く。
- 正本の本文（クリエイター正本 §10・企業正本 §13）と台帳の行が食い違うときは台帳の行を優先し、正本は新しい版で追従する。
- 写しは正本とバイト一致させる（上の SHA-256）。写しを直接編集しない。台帳の新版が出たら、写しと本表を同じ PR で更新する。

## QA がすること（`qa/decisions_check.js`）
1. 写しの SHA-256 が本表の値と一致すること（写しの改ざん・手編集を検出）。
2. 状態が「決定」で領域が「サイト」「サイト運用」「会社情報」の行は、次のどれかで検証の経路を持つこと。どれも無い行があれば QA は落ちる（決定を足したら、検査も足す）。
   - 成果物欄に `QA qa/<ファイル>` と書かれ、そのファイルが存在する
   - `qa/*.js`・`qa/run_all.sh` のコメントに `DEC-YYYYMMDD-NN` が書かれている（その検査が守る）
   - `qa/decisions_check.js` の MANUAL 表に理由つきで載っている（機械で測れない判断。配備後の目視・模擬ユーザー検査で確かめる）
