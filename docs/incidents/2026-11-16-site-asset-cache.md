# 2026-11-16: 公開HTMLとスタイルの版が揃わない

## 時系列

- PR #55の最終検証run `43848242153` が全件合格。main `08c89c6bd835076a0395cfd71ce8cc097d3e1e52` へ通常のsquash merge。
- 本番run `43850918813` の `site-verify` と `deploy` が成功。
- 配備後の `https://reyz.inc/` 実ブラウザ確認で、新HTMLの3つの `hero-route` リンクと、旧版の `site.css` が同居していることを観測。CSSOMは560規則、`.hero-route` を含む規則なし、リンクの `::after` は `none`。
- 通常の再読み込み後も同じ観測結果。公開完了の判定を保留し、内容による入口資産の版管理を実装する。

## 影響

確認した公開ブラウザで、新デザインのリンク矢印やスタイルが反映されなかった。影響した訪問者数・キャッシュ拠点数は測定していない。フォーム送信やPDF生成が失敗したという観測はないが、この状態でそれらを確認済みとは扱わない。

## 原因と確認範囲

HTMLはCSS・JavaScriptを変更前と同じ固定URLで参照していた。新しいHTMLに旧応答が組み合わされ得る構成であり、実際に読み込まれたCSSの不足を確認した。ブラウザ、CDN、origin側のどのキャッシュが旧応答を保持していたかは未特定。キャッシュ層を断定せず、URLと内容の対応を明確にする変更で対処する。

## 検知

公開後の実ブラウザの画面とCSSOMを、最終CI画像・ビルド済みCSSと照合して検知した。CIは同一チェックアウト内の配信を検証するため、公開経路に保存された旧資産の混入を再現していなかった。

## 是正と再発防止

[ADR-0014](../adr/0014-content-versioned-site-assets.md) に従い、6つの入口資産を内容hash付きファイル名で出力し、全ページの参照を揃える。canonicalと既存の版付きファイルは保持する。フォームの試験用interceptionを新しい命名へ追従させ、公開参照・hash・再生成の検査を追加する。

再発防止の実装、全関門、配備、公開後の観測は、[PR #56](https://github.com/REYZ-Inc/reyz-site/pull/56)の「検証（FACT）」で追跡する。配備後の確認を含む最終結果も同PRへ集約する。

## 教訓

配備APIの成功は、利用者が最新の組み合わせを読み込んだ証拠ではない。生成物の整合確認と公開後の実画面確認を、異なる検証として完了させる。
