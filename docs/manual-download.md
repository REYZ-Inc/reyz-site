# 配信マニュアルのカスタマイズとダウンロード

## 目的・承認された要件

2026-11-16、CEOから「REYZ Inc.のサイトの中の最適な場所からマニュアルをダウンロードできる場所を作る。ダウンロードする際に名称を入力できるようにし、色合いの選択肢をいくつかつくり、選択式にて指定した色合いでダウンロードができるように」と実装指示を受領した。

提供済みの縦9:16・42ページの配信マニュアルを使用する。本文、操作画面、図、ページ順、目次リンクを保持し、47か所の名称と文書のアクセント配色を選択可能にする。ギフト・人物・操作画面そのものの画像色は変更しない。

入力原稿: `REYZ_STUDIO_LIVE_Manual_Mobile.pdf`、8,821,085 bytes、SHA-256 `9a8757d14f089921a3f1d3ad8c550a340893cb9d1f9f12af7421f556cd0d20b1`。直近の名称差し替え版は Apex by YG。掲載内容・価格・イベントの例は原稿の記載を保持し、今回の変更で現行TikTok仕様の確認済みとは扱わない。

## 導線・画面

- 主導線は `/creator` のTikTok LIVEサービス説明の直後。既決のサービス説明文と主ナビ5項目を維持する。
- 共通フッターにも「配信マニュアル」のリンクを設ける。
- 専用ページは `/manual`。HTMLの正本は `build/build.py`、生成物は `site/manual.html`。
- 「PDFに載せる名称」入力、配色ラジオ選択、9:16の表紙プレビュー、PDF生成・保存の順で操作する。
- 名称入力は初期値なし、例は `Apex by YG`。未入力プレビューは `YOUR NAME`。名称は必須、前後の空白を除き、NFC正規化後24文字まで。制御文字・改行・未対応の字形は明示的なエラーとする。
- 選んだ名称全体を選択テーマのアクセント色で描画する。長い名称は各掲載領域内に自動で収める。名前の入力値をHTMLやPDF命令として解釈しない。
- 操作対象は44 CSS px以上、入力欄はiOSの意図しない拡大を防ぐ16px以上。ラジオ・キーボード操作・ラベル・進行状況とエラーの読み上げを用意する。

## 配色

名称と基本アクセント色は次の6種類を契約とする。補助色はアクセントに合わせた淡色・罫線・暗色へ置換する。本文の黒、白、写真・UI画像の色は保持する。

| id | 表示 | 基本アクセント |
|---|---|---|
| pink | ピンク | `#F715AC` |
| blue | ブルー | `#4169E1` |
| purple | パープル | `#8B5CF6` |
| green | グリーン | `#168B72` |
| coral | コーラル | `#D96156` |
| gray | グレー | `#737783` |

初期配色はpink。プレビューとPDFは同じテーマ定義を使い、別の値を持たない。

## 構成・API契約

ADR-0012に従い、単一の検証済みPDFテンプレートと、名称配置・配色可能な描画命令のメタデータを同一オリジンから配信する。サーバー、外部PDF生成サービス、追加の秘密情報、ログイン、メール入力は不要。

PDFエンジンはDOMから独立させる。

```js
validateName(rawName) // { valid, normalized, message }
themes // id, label, accent とプレビュー/PDFで共有する補助色
generateManual({ name, themeId, onProgress, signal })
// => { bytes: Uint8Array, fileName: string, pageCount: 42 }
```

PDF、埋込みフォント、生成ライブラリは生成操作時に遅延読込みする。全テーマのPDFを複製して配信せず、テンプレートを共用する。文字をラスタ画像に置き換えず、既存の検索・選択可能な本文と内部リンクを保持する。

依存物は固定バージョン・ライセンス・ハッシュを記録して同一オリジンへ配置する。ブラウザが名前に必要なフォントだけを選び、生成PDFでは必要字形を埋め込む。PDF生成が応答性を損なわない実行方法と、実測の時間・サイズは実装検証で確定する。

## ダウンロード・失敗時の挙動

- 生成中は名称・配色変更と重複生成を防ぐ。進行状況を表示する。
- 生成が成功したらBlobのダウンロードを開始し、生成結果に結び付いた明示的な保存リンクを残す。
- iPhoneなどで自動保存が始まらない場合は、新しいタップでPDFを開く/保存できる。ファイル共有対応端末では生成後の明示ボタンからのみWeb Shareを呼ぶ。
- 名前・配色を編集したら以前の結果を無効にし、古い設定のPDFを渡さない。
- オフライン、取得失敗、未対応文字、生成例外は具体的に表示し、入力を保持して再試行できる。
- 名前はブラウザ内でのみ使用する。URL、アクセスログ、解析、フォーム送信に含めない。
- Blob URLはクリック直後に破棄せず、設定変更、結果の置換、ページ終了時に解放する。

## 関門・検証

既存の `worker-tests` / `stack-e2e` / `site-verify` / `docs-gate` を維持する。既存のリンク、画面幅、文字色、最上部スタート検査にも新ページを含める。新機能の検査では次を確認する。

1. Creator/フッターから到達し、入力・選択・生成・保存まで通る。
2. 英数字、日本語、最大長、空白、超過、未対応字形、HTMLに見える文字列を試す。
3. 42ページ・540×960pt・47名称・内部リンクを検証する。名称以外の本文と画像を保持する。
4. 6配色をPDFから検証し、プレビューと一致する。
5. 重複クリック、設定変更、取得失敗、再試行で古いPDFを配らない。
6. 320px/390px/デスクトップ、キーボード、Chromium/WebKitを確認し、iPhone実機検証とブラウザエンジン検証を区別する。
7. 初期表示・生成時の通信と生成時間・PDFサイズを測り、名称の外部送信がないことを確認する。

実測結果はPRとQA記録に追記する。配備後は公開URLで導線と実ダウンロードを再確認する。mainの保護ルールを変更・回避しない。

### フォントの欠字是正（2026-11-16）

文字抽出だけでは検出できない欠字を実描画で再現した。修正前は「株式会社レイズ」をPDFから全文抽出できた一方、実際の表示は「株式会」までだった。元フォントは長い`loca`形式で、奇数バイトの字形境界も合法だった。fontkit 1.1.1の部分埋込みは字形データをそのまま複写して短い`loca`形式へ切り替え、奇数オフセットを2で割って切り捨てるため、一部の字形データを破損させていた。TTFとWOFFの両方で同じ欠字を再現した。

`tools/prepare_manual.py`で日本語フォントの`glyf.padding = 2`を設定し、すべての字形境界を偶数に揃えてからWOFFを保存する。配信形式と必要字形だけの埋込みは維持する。生成後は`loca`の偶数整列も検査する。全17,936字形の輪郭座標、16,732文字のcmap、文字幅とサイドベアリングが元の静的TTFと一致し、奇数オフセットは8,942件から0件になった。修正WOFFは3,358,976 bytes（増加1,852 bytes）。

英字用Poppinsでも旧WOFF2の部分埋込みが字形を破損させることを確認した。Poppinsの元TTFはすでに偶数境界であり、日本語の奇数オフセットとは別の不具合である。元TTFとWOFFは正常、元・再保存・偶数整列後のWOFF2はいずれも欠字を再現したため、英字用も元TTFから偶数整列したWOFFへ統一した。プレビューとPDFは同じ70,696 bytesのWOFFを使い、旧WOFF2を除去する。実描画は全量TTF参照と一致し、PDFには必要な字形のTrueTypeプログラムだけを埋め込む。WOFFのコンテナそのものをPDFへ全量埋め込む方式は使わない。

入力可能文字の一覧も、ASCII以外で実際に使うNotoの16,732文字のcmapから生成する。旧一覧で許可していたがNotoに存在しない202文字は、生成後の例外ではなく入力時のエラーで検出する。

Nodeで通常の日本語名、1文字、英字との混合、同字反復、24文字の5ケースを生成し、各42ページ・47名称を確認した。同じ原稿へ元TTFを全量埋め込んだ参照PDFと、独立したMuPDFで全210ページを1 pointあたり1画素のグレー画像として比較し、計108,864,000画素の差分は0だった。修正後PDFは7,049,742〜7,055,593 bytes。検索可能な文字のまま保持する。これはフォントとPDF内容の検証であり、端末のブラウザ操作確認とは区別する。

回帰検査は抽出文字列に加えてPDF.jsの実字形存在も検査する。修正前の42ページ出力は、47名称中の「社レイズ」計188字形が欠落として検出された。依存ライブラリ・フォント・ライセンス・テンプレートの12資産について、QA開始時に一覧、bytes、SHA-256を照合し、不一致は失敗とする。

## 運用・対象外

原稿内容を更新するときは、単一テンプレートと配置データを同じ変更で更新し、全42ページの回帰確認を行う。ライセンスと依存バージョンを管理する。ロールバックは通常のPRでこの変更を戻す。

今回の対象にはPDF本文の自由編集、利用者データの収集、課金、管理画面、SNSへの自動投稿を含めない。
