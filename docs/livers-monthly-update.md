# /livers（REYZ STUDIO のライバー）月次更新の手順

対象ページ: `https://reyz.inc/livers`（`site/livers.html`。`build/build.py` が `data/livers/` の最新月から生成する）

## 掲載の規則（2026-11-21 CEO 指示）

| 項目 | 規則 |
|---|---|
| 対象 | その月に 100 時間以上配信したライバーだけ |
| 並び順 | その月の獲得ダイヤモンドの多い順 |
| 見出し | 「先月」と書かない。「2026年10月」のように年月で示す |
| 載せるもの | アイコン、アカウント名（TikTok の表示名そのまま）、ダイヤモンド数（数字の横に「ダイヤ」）、配信時間 |
| 載せないもの | 円・ドルなど法定通貨に換算した金額 |
| 大きさ | 1 位が最大、2 位、3 位と小さく、4〜10 位、11〜20 位…と 10 人ごとに一段小さく |
| リンク | アイコンを押すと本人の TikTok アカウントが開く |

規則は 3 か所で機械的に守る。手で並べ替えない。

1. `tools/livers_month.py` — 100 時間以上の絞り込みと並べ替え
2. `build/build.py` — 条件に合わない名簿ではページを作らない
3. `qa/livers_check.py` — 名簿データと公開ページの一致（CI の `site-verify` で毎回実行）

## 毎月の手順（月初、前月分が確定してから）

1. **Backstage を読む。** TikTok LIVE Backstage の「クリエイターデータ」を、対象月の 1 日〜末日（UTC）で開く。
   全ページを読み、全員分の「ユーザー ID・ダイヤモンドの合計数・LIVE時間」を `raw.json` にする（絞り込まない）。
   一覧の件数（「158件のうち…」）を控える。
2. **プロフィールを読む。** 100 時間以上の人それぞれの TikTok 公開プロフィールを開き、
   表示名を `avatars/names.json` に、プロフィール画像を `avatars/<ユーザーID>.jpg` に保存する。
   開いたページの URL と表示名が、その人のユーザー ID のものであることを 1 人ずつ確かめる。
3. **名簿を作る。**

   ```
   python3 tools/livers_month.py 2026-11 raw.json avatars/ --captured-on 2026-12-01 --members 158
   ```

   出力された一覧（順位・ID・ダイヤモンド・時間・名前）を Backstage の画面と見比べる。
4. **生成して検査する。**

   ```
   python3 build/build.py
   python3 qa/livers_check.py site
   bash qa/run_all.sh
   ```
5. **PR を出す。** `data/livers/YYYY-MM.json`、`site/assets/livers/YYYY-MM/`、再生成された `site/` を 1 つの PR にする。
   本文に、対象月、人数、Backstage の件数、取得日を書く。Draft で出し、確認席の合意のあと CEO がマージする。
   マージで GitHub Pages に公開される。AI は本番への公開操作をしない。

## 載せる前に毎月確かめること

- **本人の同意。** 新しく載る人がいる月は、アイコン・アカウント名・ダイヤモンド数・配信時間の公表について本人の同意を確かめる。
- **外れる人。** 100 時間を下回った人は一覧から外れる。規則どおりの結果であることを本人に伝えられる状態にする。
- **アカウント名とアイコン。** 本人がいつでも変える。必ずその月に取り直す。

## データの形

`data/livers/YYYY-MM.json`

```json
{
 "month": "2026-10",
 "source": "TikTok LIVE Backstage（クリエイターデータ）",
 "period_utc": ["2026-10-01", "2026-10-31"],
 "captured_on": "2026-11-21",
 "threshold_hours": 100,
 "members_listed_in_backstage": 158,
 "livers": [{"id": "ユーザーID", "name": "アカウント名", "diamonds": 16450000, "hours": 158.3, "avatar": "ユーザーID.jpg"}]
}
```

過去の月のファイルは消さない（記録として残す）。ページに出るのは最新の月だけ。

## 既知の制約

- Backstage の画面は数値を「16.45M」のように上 3〜4 桁で表示する。`diamonds` はその表示値で、ページでは「万」未満を四捨五入する。
- Backstage に外部連携の口は無い。読み取りは、ログイン済みのブラウザで人または AI が行う。
- 一覧に出るのは、その時点の在籍者だけ。
