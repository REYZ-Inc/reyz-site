# REYZ サイトの情報設計

更新日: 2026-11-20（JST）

## 目的と変更の根拠

サイトを訪れた人が、自分に関係する事業、依頼できる仕事、本人が決めること、費用と条件、次の操作を理解できる構成にする。事業の説明を減らすために提供範囲を狭めるのではなく、同じ説明を繰り返す節をまとめる。

今回の変更は、作業セッションでの最新のCEO指示――全体構成を見直し、意味の薄い内容や重複を削り、画像・アニメーション・実写動画などを使って顧客に伝わる仕上がりにする――に基づく。従前の「困りごと」節の維持や、全節を残したままの装飾追加は、今回の構成見直しの前提にしない。既存の決定台帳を書き換えて過去の指示を消すことはしない。

保持する基準は、`docs/decisions/00_決定台帳_20261027.md` の会社情報・固定コピー・製品名・料金等の表示方針、および `docs/STANDARDS.md` の事実と未確認事項の区別。根拠のある実績や順位がない状態で、受賞、顧客成果、比較優位を獲得済みとは表示しない。

本書は現行の情報階層を説明する。`docs/site-experience.md` にある過去の映像構成、CTA、比較節の記述は改修履歴であり、今回変更した箇所の現行構成は本書と `build/build.py` を参照する。

## 変更前と変更後

### Home

4章の目的を維持する。`#infinity`は会社の入口、`#origin`は事業の関係、`#map`は自分の目的、`#reyz`は会社の事実を扱う。

従来の最初の∞描画スロットだけを、オリジナルの3D映像へ置き換える。同じ位置に動画と粒子の∞を二重に描かない。新しい映像専用セクションは追加しない。固定の日本語見出し、3事業へのリンク、後続章の粒子表現は残す。

### Creator

変更前の8節は `top → income → path → pain → model → services → compare → how`。変更後は5節の `top → income → model → services → how`。

- `#path`は独立した大節から、`#income`内の目的選択へ移す。6つの入口を見たあと、自分の目的に合う道を同じ文脈で選ぶ。`#path`のIDは保持する。
- `#pain`を削除する。迷い、制作負担、目的変更、費用・制限の説明は、目的別の道、支援内容、契約条件、はじめ方にそれぞれ対応している。
- `#compare`を削除する。入口を選ぶ、条件を見る、やめる自由という内容は、直前までに出ている情報の再掲だった。
- `#model`の見出しを「条件を、先に。」へ変更する。費用ゼロ・報酬からの手数料ゼロ・やめる自由、明細や契約条件は削らない。
- 実写は掲載しない（2026-11-20 改定）。掲載していたストック素材は活動の場面を映しておらず、見た人を相談に近づけていなかった。

#### 2026-11-20 の再構成（目的と競合比較からの順序）

目的は、見たクリエイターが「REYZ に任せたい」と確信し、相談に進むこと（DEC-20261023-03、2026-11-20 CEO 指示）。ページの文法を `/creative` と同じ「主張 → 確かめる → 条件 → 相談」にそろえる。

変更前の5節は `top → income → model → services → how`。節の順序と id は同じまま、中身の置き場所を変える。

- **主張（`#income`）**: 6つの収益を、ひとつの入口に。競合は収益源ごとに道具や事務所が分かれており、費用ゼロ・報酬 100% はライブ配信の事務所で広く掲げられている（2026-11-20 の調査。`docs/site-coherence.md` §3.1）。REYZ だけが示せるのは、6つがひとつの入口にあること。ストックの実写、その見出し、説明の段落は外し、経路の図と6つの入口で伝える。
- **確かめる（`#model`）**: 3つの画面の見本だけにする。見出しは「進め方が決まる。稼ぐ道が開く。収入が見える。」で、直下の「地図・入口・明細」の3つのタブに一つずつ対応する。「地図」という呼び名を、説明なしに先頭で使わない。
- **条件（`#services`）**: 約束（費用ゼロ・報酬からの手数料ゼロ・やめるのも自由）、原資の図、「はっきり決めていること」を、TikTok LIVE エージェンシーと配信マニュアルの直後に置く（2026-10-29 の CEO の見解。決定台帳への行追加は未了）。
- **冒頭の操作**: 「6つの入口を見る」（`#income`）と「相談する」。「地図をつくる」「マニュアルをつくる」は、それぞれ 3 つの画面の見本と配信マニュアルの箇所に 1 回ずつ残る。
- `MODEL`、`SCREENS_CREATOR`、`INCOMES`、`PATH_GOALS`、`PATHS`、`TT_*`、`VD_*` の値は変えていない。「目的から、道を選ぶ」は Home の地図と役割が重なるが、相談への引き継ぎに使われているため本改修では残す（次の整理の対象）。

### Creative

変更前の9節は `top → guard → pain → gain → show → services → decide → compare → how`。変更後は6節の `top → services → guard → show → gain → how`。

- `#services`を導入直後へ移す。何を依頼できるかを理解してから、その仕事の流れを見る。4束11項目の見出し・本文は保ち、動画制作の項目から`#show`へ進める。
- 主要な操作体験を`#guard`の1案件に集約する。企画、制作・確認、公開、結果、明細と、条件変更・素材差替え・期限・通信断を同じ案件の状態で示す。
- 従来の`#decide`は同じ節の補足へ移す。`details.workflow-detail`を開いたときだけ「表現確認の補足体験」が出る。メイン案件と別の短い確認例であることを見出しで区別する。
- `#pain`と`#compare`を削除する。提供内容と任せる範囲の再掲をやめ、契約前の確認事項は料金の説明と導入範囲の注記に残す。
- `#show`では紙の造形を使ったCG習作を掲載する。映像と出典に続く制作ノートで、構図、光、動きの選択を実際の画に即して説明する。
- `#gain`は提供範囲と仕事の流れの後へ移し、「確認と管理の費用を、確かめる。」とする。削減効果を実測したような見出しにしない。
- 料金の相談リンクは、表示中の試算条件と結果を編集可能なフォームに引き継ぐ。初期値の例はその旨を明記する。
- 古い「今／REYZと」の役割図は削除する。計算機内の「仕組みに任せること／人が決めること」に、より具体的な役割分担が残る。
- 冒頭で複数のクリエイター案件を進めるブランド・代理店に呼びかける。承認した素材の版と利用条件が案件ごとに残り、差し替え後は新しい版の確認から再開することを伝える。
- 最初のCTAは`#services`「依頼できること」、次は`#guard`「差し替え時の確認を試す」。最終の相談導線は`#how`に残す。

### AI

変更前の6節は `top → promise → products → enterprise → enterprise-how → principles`。変更後は4節の `top → products → enterprise → enterprise-how`。

- `promise`と`principles`で繰り返していた停止、事実、承認、記録の説明を、`#enterprise`内の「判断と情報の扱い」にまとめる。
- 紹介動画の差し替えを例に、再利用できる手順と版ごとの承認を説明する。読者は`/creative#guard`で実際に差し替えを試せる。
- AIページ内の検証アニメーションを削除する。詳しい検証の仕組みは、その製品を説明する`/consensus`に残す。
- 特定の提供元に固定しない構成の説明を、AI Orchestrationの製品説明へ移す。
- 既存の`#enterprise`を、仕事を重ねる価値を説明する場所にする。新しい大節を追加しない。

公開コピーは「つくった仕組みを、次の仕事へ。」を見出しに、以下の3点を具体化する。

1. 業務に合わせて作った機能を、次の案件でも使える形に整える。
2. 完了条件を先に決め、成果物と実行結果を確かめる手順を機能と一緒に残す。
3. 目的・条件が変わったときに、影響する成果物・承認・公開先を追い、必要な範囲をやり直す。

顧客の記録や秘密情報と、共通の機能・確認手順は分けて扱う。他の案件での再利用は許諾された範囲に限る。公開ページに社内用の「検査辞書」「関所」「IPの蓄積」といった語を追加して説明を長くしない。

## 保持したコピー・料金・操作

固定コピーと会社情報は本改修で改定していない。生成元のAST比較で、`BIZ`、3つの`ADDR_*`、`PROFILE`、`TT_P1`、`TT_P2`、`TT_NOTE`、`VD_H3`、`VD_P`は変更前と同一だった。クリエイターの「相談・設計・伴走」の本文、固定の導入文も保持する。

`MODEL`、`SCREENS_CREATOR`、`SCREENS_ENT`、`GAIN`、`INCOMES`、`PATH_GOALS`、`PATHS`の値も変更前と同一。見本の補足表示、条件の説明、表示単価を配置変更に合わせて削っていない。

企業向けの掲載料金は月額50,000円・20本まで、21本目から1本1,250円。公開前の確認は月30件まで無料。入力する作業時間と人の費用は読者の仮定であり、結果はREYZの実測削減効果ではない。対象素材、無料と有料の範囲、単位・再確認の数え方、連携、制作・出演・広告・導入費、税、契約期間・解約条件は、既存の見積もり確認文を保持する。今回の構成変更から新しい料金条件を作っていない。

## 確認範囲と未確認事項

本改修で確認できるのは、公開サイトの構成、コピー、見本、料金表示、操作とメディアの実装である。以下をサイトの検査から立証した扱いにしない。

- 商用REYZ PLATFORMの全業務実行、複数AIによる実審査、広告・投稿の実公開、実際の報酬精算。
- 全顧客業務での実行機能の再利用率、費用削減、品質改善、他社比較の優位。
- TikTokとの契約当事者、商用APIの利用権限、委託・報酬・OEM等の契約条件。
- 受賞水準の第三者評価、顧客に必ず選ばれること、実利用者の理解率や成約率。

未入手のGoogle Drive正本を読んだとは記録しない。今回はリポジトリ内の決定台帳・実装と、作業セッションで共有された方針を照合した。事業上の提供方針を示すコピーと、公開サイト内で実際に動作する操作見本の証拠は分ける。

### 実写の手動停止が維持されない不具合と是正

最初のcycle実行は472指標で2件の失敗を記録した。両方ともWebKit 390pxのCreator実写に起因する。手動停止後のスクロールで停止が維持されず、続く「映像を再生」の操作が30秒でタイムアウトした。直前の画面外停止は成立しており、外部mutation要求も0件だった。失敗結果と画像は`cycle.json`と`cycle/`に保持する。

既存の`mediaJourney`をそのまま使い、WebKitのCreator実写1件だけにnativeイベントの観測を追加して再現した。`play()`・`pause()`・時計の置き換えは行っていない。ボタン・メディアのイベント、別のnative IntersectionObserver、表示状態の変化、nativeの`performance.now()`を記録した。

修正前は4,095msに停止クリックが入り、4,096msに`paused=true`と「映像を再生」を確認した。その127ms後、追加クリックなしにnativeの`play`が発火し、`playing`とともに再生状態へ戻った。クリックは正しく停止を実行していたが、その後の再生イベントで最新の停止意図を再適用する処理がなかった。h1へ戻った位置でも動画の約55.5%が可視で、可視率20%の閾値を下回っていなかった。

製品側で再生の意図と要求の世代を保持し、nativeの`play`・`playing`および遅れて完了する再生要求の後にも、最後の停止意図を適用するよう是正した。古い要求の失敗が新しい再生要求を消さないようにした。

是正後の同じ限定診断は1回・15判定で全件通過した。遅延したnative再生も実際に発生したが、4,452msの停止、4,571msの遅延`play`に続き、4,573msの`playing`時点では`paused=true`を維持し、4,576msに`pause`を記録した。以後のスクロールでも停止を維持し、5,098msの本人の再生クリックで再開した。修正前後の時系列は`webkit-media-trace/attempt-1.json`と`webkit-media-trace-after/attempt-1.json`に分けて保持する。
